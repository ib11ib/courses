# Урок 18. Как писать программу и искать ошибки

← [[Урок 17 — Модули и стандартная библиотека]] · Следующий: [[Проект 1 — Игра Угадай число]]

**Цель:** перед проектами научиться главному навыку программиста — превращать задачу в план, а потом находить и исправлять ошибки.
**Время:** 1–2 дня.

## Почему это важно

Знать команды — это как знать слова иностранного языка. Но чтобы говорить, нужно уметь строить фразы. Программисты больше всего времени тратят не на набор кода, а на **обдумывание** и **поиск ошибок**.

## Шаг 1. Разбить задачу на части (декомпозиция)

Задача: «Программа учёта расходов». Слишком большая — непонятно, с чего начать. Делим:

1. Хранить список расходов (сумма, категория, дата).
2. Добавлять расход.
3. Показывать все расходы.
4. Считать итог по категориям.
5. Сохранять в файл и загружать.
6. Меню, чтобы выбирать действия.

Каждый пункт — уже понятная маленькая задача. Каждый пункт часто = одна функция.

## Шаг 2. Псевдокод

Псевдокод — план программы обычными словами, но в структуре кода:

```
загрузить расходы из файла
повторять:
    показать меню
    спросить выбор
    если 1 — спросить сумму и категорию, добавить, сохранить
    если 2 — для каждого расхода напечатать строку
    если 3 — посчитать суммы по категориям (словарь), напечатать
    если 0 — выйти
```

Потом каждую строчку превращаете в код. Писать псевдокод можно прямо в файле `.py` в комментариях `#`, а потом под ними писать код.

## Шаг 3. Писать маленькими шагами

**Главная ошибка новичка** — написать 100 строк и потом запустить. Ошибок будет 15, и непонятно, откуда.

Правильно: написали 5–10 строк → запустили → работает → пишем дальше. Как при ремонте: проверяем, что каждая розетка работает, прежде чем закрывать стену.

## Поиск ошибок (отладка)

### Приём 1. Читать traceback целиком

Когда ошибка случилась внутри функции, сообщение длиннее:

```
Traceback (most recent call last):
  File "D:\Python_курс\shop.py", line 12, in <module>
    print(average(grades))
  File "D:\Python_курс\shop.py", line 5, in average
    return total / len(numbers)
ZeroDivisionError: division by zero
```

Читаем **снизу вверх**: ошибка — деление на ноль, на строке 5 в функции `average`. А вызвали её со строки 12. Значит, нужно понять, почему туда пришёл пустой список.

### Приём 2. Отладочный print

Не понимаете, что лежит в переменной? Выведите её:

```python
print("DEBUG grades =", grades, type(grades))
```

Потом эти строки удалите.

### Приём 3. Отладчик VS Code

VS Code умеет выполнять программу **по шагам** и показывать все переменные.

1. Кликните **слева от номера строки** — появится красная точка. Это **точка остановки** (breakpoint). Или клавиша `F9`.
2. Запустите не ▶, а через **F5** (выбрать «Python File», если спросит).
3. Программа остановится на красной точке. Слева, в панели **Variables**, видны все переменные и их значения.
4. **F10** — выполнить одну строку и перейти к следующей. **F11** — зайти внутрь функции. **F5** — продолжить до следующей точки. **Shift+F5** — остановить.

Это как трассировочная таблица из урока 08, только её рисует сам компьютер.

### Приём 4. Резиновая уточка

Известный приём программистов: объясните свой код вслух, строчка за строчкой, воображаемому слушателю (или резиновой уточке на столе). На середине объяснения часто сами видите ошибку. Это работает удивительно хорошо.

### Приём 5. Правильно спрашивать нейросеть

Плохой вопрос: «не работает, помоги». Хороший вопрос содержит:
1. Что программа должна делать.
2. Код.
3. Что вы вводили.
4. Что ожидали увидеть.
5. Что увидели на самом деле (полный текст ошибки).

Так устроены все промты в этом курсе.

  def average(numbers):
      total = 0
      for n in numbers:
          total =+ n
      return total / len(numbers)

  grades = []

      grade = input("Оценка (пусто — конец): ")

## Запомнить

- Большая задача → список маленьких → псевдокод → код.
- Пишем по 5–10 строк и сразу запускаем.
- Traceback — снизу вверх. Отладчик: `F9` — точка, `F5` — старт, `F10` — шаг.
- Хороший вопрос: что должно быть, код, ввод, ожидание, реальность.
